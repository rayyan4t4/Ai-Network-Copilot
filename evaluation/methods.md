# Final study protocol

The experiment uses 70 newly acquired real GNS3 instances: 10 for each of five fault classes, 10 healthy and 10 insufficient-evidence cases. Pilots are separate and retained. A seeded randomized schedule fixes case order and branch assignment before final acquisition. Each instance uses a fixed capture offset in profile.json, followed by restoration and fresh successful monitoring of all 30 nodes. Capture is never delayed until the diagnostic algorithm gives a desired answer. Invalid interventions or failed restoration stop acquisition for investigation. Original captures and all failures are retained.

Faults are administrative shutdown of a branch router LAN interface, OSPF passivity on that interface with the physical link up, an exact monitor-to-host nftables drop on a branch MLS, sustained UDP demand on a branch WAN with a constant 2 Mbps effective egress capacity, and ICMP suppression on one host. The last class establishes probe unreachability, not a powered-off device. The same capacity and acquisition cadence apply in every condition. Monitoring cadence is 10 second SNMP, 3 second probes and 15 second console snapshots, subject to measured collection/export overhead on the shared laptop. This is an experimental profile, distinct from the earlier 30/10/45 second operational profile.

Insufficient-evidence cases are separately injected real faults, two per class. A prespecified mask withholds Syslog events for shutdown/OSPF, older ACL snapshots needed for counter deltas, the verified capacity-source metadata for utilization, or interface snapshots and samples needed for upstream checks in reachability. Masks operate on copies. Original observations remain intact. Missing evidence is not a fabricated observation. Rate values remain measured, but capacity unavailable in the masked condition must be stated as unavailable.

Four approaches process the same immutable input instance. B1 uses direct uncorrelated link-down, utilization and probe alerts without topology or a model. B2 gives Gemini a short rule-generated description without structured evidence. The no-gate variant and full system use identical normalized facts, candidate hypotheses, curated guidance, prompt, model settings and structural validation. Only the full system applies the evidence gate before calling Gemini. The response schema permits every fault class, healthy and inconclusive, and never forces the expected label or target. Candidate hypotheses are observed rule outputs, not intervention labels. Ground truth is isolated in control files and is unavailable to every diagnostic adapter.

The gate is a weighted fraction of available required signals. A score at least 0.8, every critical signal and no contradiction are required. It is not a calibrated confidence probability. OSPF localization uses an observed deviation from a verified healthy configuration as well as persistent lost neighbors, link-up evidence and an identified event. Generic dependent probe failures remain symptoms when a stronger observed root candidate exists. Choosing the primary hypothesis uses a fixed class priority and then affected-device count and device ID.

All model transmissions obey the existing consent: normalized lab device names, interfaces, timestamps, topology paths, evidence identifiers and controlled summaries/curated guidance only. No addresses, raw logs, raw configurations, lab credentials or intervention labels leave the laptop. The pinned model is gemini-3.5-flash-lite with temperature 0 and 1400 output tokens. Requests are at least 15 seconds apart. One uniform retry is allowed for HTTP 503 after 30 seconds or 429 after 60 seconds. Original attempt responses and delays are retained. Total study requests including pilots are capped at 260. Provider errors are reported, never replaced with invented responses. Billing settings are unchanged.

Detection precision, recall and F1 use 50 diagnosable fault instances and 10 healthy instances. A provider failure cannot count as a successful healthy classification and is conservatively charged as a false positive on a healthy instance. Exact root accuracy uses all 50 fault instances: class, device and interface where defined must match. An inconclusive or failed response is wrong on a diagnosable fault. Correct abstention uses all 10 insufficient instances; an API error is not a correct abstention. Per-fault accuracy, confusion tables, failure counts and Wilson intervals accompany aggregate metrics. Shared hardware and repeated topology conditions limit generalization and independence.

Replay pipeline latency measures processing of a recorded window to result-file availability and includes local request-spacing waits. API attempt duration is separate. These timings do not establish injection-to-browser-display latency. The viewer can record browser render acknowledgements, but browser access was rejected in this session. The report must therefore leave incident-to-display latency and visual UI verification unverified unless a real browser session later supplies that evidence. Do not synthesize display acknowledgements.

Two independent real team reviewers assess blinded interpretations using the same observations, counting unsupported factual claims and rating recommendation relevance, read-only status, evidence support and usefulness. Initial forms remain blank until completed by humans. Automated schema/citation checks do not substitute for semantic review. Confirm/reject/correct feedback is persisted without learning. Academic authorship, institutional formatting and submission remain the team's responsibilities.
