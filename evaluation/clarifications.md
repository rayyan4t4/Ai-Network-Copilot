# Clarifications for interpreting the frozen study

These notes do not change frozen algorithms, input instances, labels or scoring.

- The B1 implementation also reads direct identified OSPF loss events and clears them on a current positive neighbor snapshot. The shorter description in the frozen methods file omitted this detail. The frozen source is authoritative.
- Detection for structured approaches is the deterministic correlator incident flag; B2 uses its model classification. Diagnosis accuracy separately scores the returned class and exact location. Healthy confusion rows should be read alongside detection scores.
- Detection metrics use conservative error imputation: a failed approach output counts as a false negative on a fault and a false positive on a healthy window, even if a prior correlator alert existed. Thus the reported pipeline detection scores include availability/validation failures and are not pure raw-correlator precision and recall.
- Healthy recorded windows are supplied to structured model comparisons to audit their classifications even without a correlator alert. The live application normally queues model work only for sufficient active incidents. This extra healthy-window audit can expose model output validation failures that would not create a live incident.
- Pipeline timing ends when a result record is prepared for persistence. It includes local request spacing and retries but excludes the final JSON file write and browser rendering. The last attempt API duration is the per-result API value; all individual attempts remain in attempt_history. No injection-to-display metric is established.
- Interface byte counters on this virtual datapath may count offered traffic before queue drops. The utilization experiment measures demand relative to a configured effective capacity reference, not verified delivered throughput on physical hardware.
- Human ratings, semantic support rates, inter-reviewer agreement and new UI visual verification are pending. No automated test row is human research feedback.
- The earlier Week 2 explanation adapter constrained a response to its observed rule candidate or abstention and is retained for legacy records. Week 3 live integration now uses the same frozen packet builder, unrestricted classifier and evidence gate as the study. It checks for a fresh matching window and displays the returned class, target and disposition separately from the rule candidate. Study figures remain recorded-window replay measurements; healthy model audit calls, retry accounting and browser timing differ from ordinary live queuing.

- Post-study operational maintenance added per-device latest-row views and indexes for the unchanged export queries. A separate live bridge adapter now collects snapshots independently of the frozen export/analysis/lifecycle cycle. No final observation, approach output, frozen source hash, original metric or reported timing was regenerated. The follow-up API freshness observation is a bounded service check and is not incident-to-browser-display latency.
